implement-task：一張 ticket 一個 worker

派工單位從 task 改成 ticket。ticket 之間依 blocking edges 平行，ticket 內由同一個 worker 序列做完每個 task。整合改成 merge 整條 ticket 分支回原本的分支，完成一張不停不問。

共識

  • 派工單位：一張 ticket 一個 worktree 加一個 fresh sub-agent；frontier 是 blockers 全部 done 的 ticket。
  • task 的角色：worker 的 checklist 兼短目標。照順序做、各跑自己的 Validation、各自一個 commit。to-tasks 保留。
  • 邊界：整張 ticket 所有 task 的專案聯集。同 ticket 內可回頭補改；跨出才 needs-triage。
  • 整合：orchestrator 自己 git merge --no-ff，然後跑 ticket acceptance、tick checkbox、票設 done、commit tracker，重算 frontier。
  • 失敗：那張 ticket 整張不合併、保留 worktree 與分支；不派新 ticket，但進行中的 worker 做完照常合併；失敗 ticket 的下游不派。
  • context 用完：worker 回報 claimed 加 checkpoint（最後一個已 commit 的 task）；orchestrator 派新 worker 到同一個 worktree 從下一個 task 接續。
  • code-review：所有 ticket 合併完才跑一次。發現全部交給一個修復 worker（邊界是本輪所有 ticket footprint 的聯集），修完合併、重跑驗證；超出範圍的才回報。
  • 單 task 入口：保留，直接跑 execute.md 做那一個 task。

Orchestrator 主迴圈

綠線是回到「計算 frontier」的循環，藍色虛線是「同一個 worktree 接續」的續派。正常出口只有一個：frontier 空且沒有 worker。

Worker：做一張 ticket（execute.md 的 delegated mode）

一次讀完 ticket、design.md、所有 task 和規則檔，然後逐 task 跑「claimed → 實作 → Validation → commit」。每個 commit 都是存檔點。
